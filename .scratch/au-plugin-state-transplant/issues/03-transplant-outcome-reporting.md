# 03: Transplant outcome reporting

**What to build:** The conversion report clearly distinguishes which plugin instances were transplanted (real state carried over) from which fell back to suggestion-only, with a stated reason for every fallback (not installed, not an AU plugin, no AU support on this platform), plus a flag when the installed version differs from the version Logic used. This is what lets the project owner know what to manually double-check before sending a converted project to a collaborator, per the spec's core promise: never silently produce a "looks loaded but is actually wrong" result.

Demoable via `--report-only` on a project with a mix of transplantable and non-transplantable plugins: the report names each instance's outcome and, for fallbacks, why.

**Blocked by:** 02

**Status:** resolved

- [x] The report lists, per plugin instance, whether it was transplanted or fell back to suggestion-only.
- [x] Every fallback states its specific reason (not installed / not AU / platform has no AU support).
- [x] A transplanted instance whose installed version differs from the version recorded in the Logic project is flagged in the report (not blocked — the transplant is still attempted — just flagged for the user to double-check).
- [x] Report-generation tests cover at least one of each outcome (transplanted, each fallback reason, version-mismatch-but-transplanted).

## Answer

**Implemented.** The per-plugin transplant decision is now a single shared function, `decide_transplant()` in `logic2ableton/au_transplant.py`, returning a `TransplantOutcome` dataclass (`status`, `reason`, `version_mismatch`, `logic_version`, `installed_version`). Both `ableton_generator._insert_transplanted_plugins()` (what actually gets written into the `.als`) and `report.generate_report()` (what the user reads) now call this same function, so the report can never describe an outcome that disagrees with what the generated file actually contains. `status` is one of `"transplanted"`, `"no_captured_state"`, `"platform_unsupported"`, `"not_installed"`, checked in that order (no captured state is checked first since it blocks regardless of anything else; platform support is checked before consulting the installed-component registry so a non-macOS run gets the specific "this platform has no Audio Unit support" reason rather than the generic "not installed").

`report.py`'s `PLUGINS FOUND` section now prints, per instance, either `-> Transplanted: exact Logic state carried over` (with an appended `VERSION MISMATCH: ...` note when flagged) or `-> Suggested: ... (not transplanted: <reason>)`. The registry scan (`installed_au_components()`/`installed_au_component_versions()`) runs once per report, not once per plugin, and is skipped entirely when no plugin instance has captured state — same perf reasoning ticket 02 already established for `generate_als`. The pre-existing `NOT TRANSFERRED` bullet "Plugin settings/parameters (not compatible across DAWs)" was also corrected: it was flatly false for any project with at least one transplanted instance, so it's now conditioned on whether anything was actually transplanted.

**`au_registry.py`** gained `installed_au_component_versions()` (identity triple -> the bundle's own declared `version` int from its Info.plist `AudioComponents` entry), `format_au_version()` (decodes the packed `0xMMMMmmbb` int to a "major.minor.bugfix" string), and `au_platform_supported()` (`sys.platform == "darwin"`).

**Real findings that deviate from the ticket's assumption on the version field** (checked against real installed bundles and two real Logic projects on this machine, not guessed):

- The *installed* side's version is exactly what the ticket expected: a real `.component` bundle's `Info.plist` `AudioComponents` array entry carries an integer `version` key, packed as the classic Apple `0xMMMMmmbb` (major/minor/bugfix) scheme. Confirmed against FabFilter Pro-Q 4 4.02 installed on this machine: `version = 262146` (`0x00040002`) decodes to `4.0.2`, matching its own `CFBundleShortVersionString` ("4.02").
- The *Logic* side's version is **not** what the ticket assumed. `PluginInstance.raw_plist` does have a `"version"` key, but sampling a real multi-plugin Logic project (704 third-party plugin instances across FabFilter, SoundToys, iZotope, Xfer, Waves, Native Instruments, oeksound, Arturia, Soundtoys, etc.) found it at exactly `0` for 686 of them (97%), with the only non-zero value seen being `1` (one Xfer plugin) — nowhere near a real release version like "4.02". This is consistent with Apple's own AU `ClassInfo` convention, where this key (`kAUPresetVersionKey`) is a *preset-dictionary format version*, not the plugin's software version — a completely different number space than the installed component's bundle version. Comparing them literally as the ticket's wording implies would flag a "version mismatch" on nearly every third-party plugin in nearly every real project, which is noise that would train users to ignore the flag — directly undermining the feature's purpose. `decide_transplant()` therefore treats a Logic-recorded version of `0` as "nothing useful was recorded" and never flags it; only a non-zero recorded value is compared against the installed component's version. This is a deliberate, documented divergence from a literal reading of the ticket, not a silent workaround — see the `decide_transplant()` docstring in `au_transplant.py` for the full reasoning and the sampled numbers.
- Consequently, "not AU" and "not installed" collapsed into a single fallback reason (`not_installed`, worded "not installed as an Audio Unit on this machine"): `au_registry.py` only scans AU component bundles, so it has no way to tell "this plugin isn't installed in any form" apart from "this plugin is installed, but only as VST3, not AU" — both just mean the identity triple is absent from the AU scan. Rather than fabricate a distinction the data can't support, the report states the one true fact: it isn't registered as an AU plugin on this machine. `platform_unsupported` remains its own distinct, genuinely observable reason (checked via `sys.platform`, independent of the registry scan).

Tests: 5 new cases in `tests/test_au_registry.py` (version decoding, a bundle with no declared version, platform detection), 7 new cases in `tests/test_au_transplant.py` (`decide_transplant`'s four statuses plus the three version-mismatch branches), and 5 new cases in `tests/test_report.py` (one per outcome: transplanted, each of the three fallback reasons, and version-mismatch-but-transplanted). Full suite: 676 passed, 61 skipped, same 2 pre-existing unrelated VST3-scanner failures as before this work (a real VST3 plugin on this machine leaking into an isolation test — not introduced by this change). `ruff check logic2ableton/ tests/` is clean.
