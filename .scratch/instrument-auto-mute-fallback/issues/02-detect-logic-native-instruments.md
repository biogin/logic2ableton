# 02: Detect Logic-native instruments so auto-mute covers them too

**What to build:** Ticket 01's auto-mute only fires when an *extracted* `aumu`-type plugin instance exists and fails to transplant. But Logic's own stock instruments (ES2, Alchemy, Sampler, Drummer, etc.) don't serialize as embedded AU-state plists at all — confirmed empirically this session against real projects (e.g. a track named "Juno 60 emulation," note-bearing, clearly meant to produce sound, whose channel strip yielded five extracted plugin instances, all effects, with the actual instrument completely absent from the byte range) — so they're invisible to extraction entirely. Today, a track like that gets *no* fallback at all: not muted, not reported, just silently produces nothing in Ableton. This closes that gap using a signal already fully decoded: a channel strip's `kind` field (`0x43` = "instrument" strip type, read since ticket 01 of the `au-plugin-state-transplant` spec). A `kind == 0x43` strip with zero extracted `aumu` instances at all — not "found but failed," genuinely none — gets the same auto-mute and report treatment ticket 01 already built, just with honest wording since the specific plugin was never identified.

**Blocked by:** None (can start immediately) — extends ticket 01's already-merged mechanism, doesn't depend on new work.

**Status:** ready-for-agent

- [ ] Report wording for this case is honest about not knowing what the instrument is — e.g. "instrument not identified (likely a Logic-native instrument)" — distinct from ticket 01's existing "missing instrument (`<manufacturer>/<subtype>`)" wording, which implies a specific, known plugin.

## Further notes

- This is explicitly detection-only, not identification or mapping — it does not attempt to determine *which* Logic-native instrument is present, or map it to an Ableton equivalent. That's a separate, larger problem (stock-instrument-to-stock-instrument mapping, tracked as `.scratch/logic-to-ableton-fidelity/issues/03-stock-instrument-effect-mapping-table.md`), deliberately decoupled: this ticket only needs to stop the track from silently producing nothing, not make it sound right.
- Found and scoped via a grilling session triggered by a direct question: "do you think mapping stock instruments is essential for someone hearing the full track without losing instruments?" The investigation that followed found this detection gap was more urgent than the mapping question itself — the existing auto-mute safety net (ticket 01) has a blind spot for exactly the class of plugin it was built to protect against going silent.
